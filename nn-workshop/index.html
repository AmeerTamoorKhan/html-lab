Suggested runs (each ~10 s): (1) Huge, 12 fields → overfit: wiggly curve, validation error rises. (2) Tiny → underfit: an S-curve that can't make the hump, both errors high. (3) Medium → good: smooth hump, errors close. (4) Huge + 80 fields → overfitting mostly gone (more data). (5) Huge + 12 fields + strong regularisation → smooth again. The scoreboard keeps each run so you can compare. Dashed grey = true relationship; best possible error ≈ 0.25 (the noise).






 
Underfit, just right, overfit: what causes each?

 
Top: the model's curve through the data. Bottom: — training and — validation error over epochs.

 
😴 Underfit

 
 
 
You see: a stiff line that misses the hump; both errors stay high.

 
Caused by: model too simple (too few neurons/layers), too few epochs, or too much regularisation.

 
Fix: bigger network, train longer, less regularisation, better features.
✅ Just right

 
 
 
You see: a smooth curve through the middle of the dots; both errors low and close.

 
Caused by: model size matches the amount of data; stopped at the right time.

 
Fix: nothing! Evaluate once on the test set.
🤓 Overfit

 
 
 
You see: a wiggly curve hitting every dot; training error tiny, validation error rising.

 
Caused by: model too complex for the data: too many parameters, too few/noisy examples, trained too long.

 
Fix: more data, early stopping, dropout, regularisation, smaller network.

Think of model capacity vs data. Underfit: the model can't express the pattern. Overfit: it has so much freedom that it also learns the noise. Same picture as the overfitting lab you just ran.






 
Classifiers: where does it get confused?

 
Rows = truth, columns = guess. Click a cell, read the formulas.

 

  

   

   

  

  

   

   

  

 

 
TP = correctly found, FP = false alarms (predicted this class but wrong), FN = missed (really this class but predicted something else). Precision: when it says Chinstrap, how often right? Recall: of all real Chinstraps, how many found? F1 balances the two.

🧹 Preprocess (always)
① split first (train / val / test)
② fill or drop missing values
③ one-hot encode categories
④ scale numbers: mean 0, std 1
all statistics from the training set only

  
🧠 Network & training
hidden: "relu", 1–3 layers of 16–64
optimizer: "adam", lr 0.001
batch size 32 · epochs ~100
+ early stopping on val loss (patience 10)

  
🩺 If it goes wrong
overfit (val ≫ train): dropout 0.2–0.5, L2, smaller net, more data
underfit (both high): bigger net, more epochs
NaN / stuck: scale inputs, lower lr
always compare with a simple baseline
